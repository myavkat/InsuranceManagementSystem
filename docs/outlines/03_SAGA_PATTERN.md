# SAGA Pattern Outline (Choreography)

## Principles

- **No central orchestrator.** Each service is autonomous — it listens for events, performs local work, and publishes the outcome.
- **Correlation via `sagaId`.** Every event in a saga carries the same `sagaId` (UUID generated by Estimation Service).
- **Compensation by event.** If any step fails, `EstimationFailed` triggers rollback in participating services that performed reversible work.

---

## Event Flow — Create Insurance Estimation

```
Estimation Service          Customer Service        Vehicle Service         Insurance Service
      │                           │                       │                       │
      │─── EstimationRequested ───┼───────────────────────┼───────────────────────┤
      │                           │                       │                       │
      │                     ┌─────▼──────┐         ┌──────▼──────┐               │
      │                     │ Validate    │         │ Validate    │               │
      │                     │ Customer    │         │ Vehicle     │               │
      │                     └─────┬──────┘         └──────┬──────┘               │
      │                           │                       │                       │
      │◄──── CustomerValidated ───┘                       │                       │
      │◄──── VehicleValidated ────────────────────────────┘                       │
      │                                                                           │
      │                                                    ┌──────────────────────▼──┐
      │◄───────────────────────────────────────────────────│ Wait for both events   │
      │                                                    │ Calculate premium      │
      │◄──── PremiumCalculated ────────────────────────────└──────────────────────┬──┘
      │                                                                           │
   ┌──▼──────────┐                                                                │
   │ COMPLETED    │                                                                │
   └──────────────┘                                                                │
```

**On failure:**
```
Estimation Service          Customer/Vehicle/Insurance
      │                           │
      │◄──── *Invalidated ────────┤
      │◄──── CalculationFailed ───┤
      │                           │
   ┌──▼──────┐                    │
   │ REJECTED│───EstimationFailed─► Rollback
   └─────────┘
```

## Event Catalog

| Event | Producer | Consumer(s) | Topic |
|-------|----------|-------------|-------|
| `EstimationRequested` | Estimation Service | Customer, Vehicle | `estimation.saga` |
| `CustomerValidated` | Customer Service | Insurance | `estimation.saga` |
| `CustomerInvalidated` | Customer Service | Estimation | `estimation.saga` |
| `VehicleValidated` | Vehicle Service | Insurance | `estimation.saga` |
| `VehicleInvalidated` | Vehicle Service | Estimation | `estimation.saga` |
| `PremiumCalculated` | Insurance Service | Estimation | `estimation.saga` |
| `CalculationFailed` | Insurance Service | Estimation | `estimation.saga` |
| `EstimationFailed` | Estimation Service | All participants | `estimation.saga` |

---

## Event Schema (Common Envelope)

```json
{
  "sagaId": "uuid",
  "eventType": "CustomerValidated",
  "timestamp": "2026-06-20T12:00:00Z",
  "traceId": "uuid",
  "payload": { }
}
```

Each service-specific payload carries the data needed for the next step (e.g., `PremiumCalculated` payload includes the premium amount and breakdown).

---

## Idempotency

- Every consumer maintains a **deduplication table** (or in-memory set with TTL) keyed by `(sagaId, eventType)`.
- If a duplicate event arrives, the consumer logs it and skips processing.
- Kafka's log compaction ensures at-least-once delivery; the consumer handles dedup.

---

## Timeout

- The Estimation Service runs a scheduled task (e.g., `@Scheduled` or `ScheduledExecutorService`) that checks for pending `STARTED` estimations exceeding a configurable timeout (default: 5 minutes).
- On timeout, the estimation is set to `REJECTED` and `EstimationFailed` is published.

---

## Compensation

| Service | Reversible Action | Compensation |
|---------|-------------------|--------------|
| Customer Service | (none — read-only validation) | Log only |
| Vehicle Service | (none — read-only validation) | Log only |
| Insurance Service | (none — calculation is stateless) | Log only |
| Estimation Service | PENDING estimation | Set to REJECTED |

> **Note:** Current SAGA flow is predominantly read-only validation. Compensation becomes critical when services perform writes (e.g., reserving inventory, deducting credits) in future extensions.
